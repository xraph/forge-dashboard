# Durable execution operations

You can inspect persisted Dispatch executions at `/@dispatch/durable`. Select an authorized namespace or enter its exact name. Discovery scans a bounded catalog and may return no visible namespaces while `complete` is false. Continue that scan before treating it as finished. Discovery grants do not imply execution access.

The execution list filters workflow ID, workflow type, build and raw state. Runs link through three independently encoded identity parts: namespace, workflow ID and run ID. Each route segment uses `v1.` followed by canonical unpadded base64url of the exact UTF-8 bytes, so the installed router cannot alias a literal `%2F` with a slash. Leading U+FEFF remains identity data; decoding does not remove it as a byte order mark. Malformed, noncanonical and earlier percent-encoded detail links are rejected with an execution-list recovery link. Regenerate earlier detail bookmarks from that list. The Go identity remains unchanged. Filter, target, client and host authorization/context clear changes restart pagination before the next read. Ordinary invalidation, polling and transient refresh retain the current cursor. Every continuation offers Restart pagination outside the data-only boundary, including refused or expired cursors. A continuation keeps its opaque cursor; Restart pagination asks for a fresh first page. Totals stay unavailable. Detail pages expose persisted history, task attempts and deadlines, authorized run chains and children, and separate Chronicle/Relay source delivery facts. Secondary execution metadata and direct run links sit in an accessible disclosure.

Counters stay decimal strings. The types mirror the exact JSON tags in Dispatch's `operator/testdata/durable-wire.json`, copied unchanged into `test/durable-wire.json`. History pages report their captured high water. Task pages report the observed run revision; they have no invented creation time. Partial run/child access remains explicit. Metadata inspection works when the exact historical build runtime is unavailable, while commands and workflow queries require their exact registered runtime and separate grants.

Each explicit payload reveal calls `durable.payload` directly through the scoped client. It requires the server's payload grant and durable audit acceptance. Base64 bytes decode as original UTF-8 text without parsing or reserializing numbers. The existing lazy JSON viewer displays that text; invalid UTF-8 remains a binary payload. Reveals stay in component memory, outside QueryStore, URLs, browser storage and telemetry. Hide, a hidden tab, a target change, client replacement or loss of metadata access removes the reveal.

Metadata uses the existing Read/useDispatchQuery, query invalidation and cursor helpers. The shared query client/store accept cancellation and `resetOnContextChange` for opted-in reads. QueryStore exposes a context epoch that changes only on clear. These reads drop captured requests on clear, then fetch after the page constructs current params; default readers keep the existing watched-key reissue behavior. Active readers determine the shared key policy: any opt-in prevents captured replay, and removing the last opt-in restores ordinary behavior. Mixed ordinary readers wake through that key's reset version after React renders. Direct store callers retain an explicit request-policy fallback when no managed readers exist. When the last reader unmounts or pauses, HTTP aborts and generation fencing excludes late results even if the transport ignores abort. Polling refreshes visible first pages every ten seconds and pauses hidden tabs. Continuation pages keep their cursor and offer explicit refresh. Transient same-scope failures retain an observed timestamp and stale label; denied, missing or switched scope data disappears.

Execution and task states use a stable semantic display mapping. Ordinary states use quiet outline badges. Failed executions and blocked delivery sources use destructive badges because they require attention; filters let you find them without relying on the current page's distribution. Source pending includes blocked. Sink accepted proves verified durable source acceptance. It does not establish Relay endpoint delivery or Chronicle external anchoring, both unavailable through this contract.

## Commands and workflow queries

You can start a workflow or signal with start from an explicit namespace. Enter the exact workflow identity, proposed run, type, build and queue. Signal with start atomically signals the current open run or creates the proposed run; the acceptance link uses the run actually accepted. Run detail offers signal and request cancellation against its explicit run and persisted build. Capability checks describe available actions, and the server authenticates and authorizes every attempt again. Cancellation acceptance says requested. Worker execution determines the eventual terminal state.

Before the first send, the page freezes the operation, complete payload, explicit target/build, durable request ID and envelope key. A lost response leaves acceptance uncertain. Close and reopen the dialog to retry that exact request, including its original bytes, after ordinary refresh or invalidation. A later denied attempt does not establish that the earlier attempt failed to commit. The submitted snapshot cannot be edited; abandon the local retry explicitly to create a new request. Abandoning it does not cancel backend work. Retained inputs and results live only in mounted page memory. Navigation, reload, client replacement or host identity/context clear discards them. There is no browser persistence or cross-session retry journal.

Text input encodes the editor's current UTF-8 value without JSON parsing or numeric normalization. Native textareas use browser line endings. To preserve original CRLF, BOM or binary bytes, choose the optional exact-byte file input, bounded to 1 MiB before reading. Loaded file bytes replace the text draft; editing text or choosing Use text input replaces the file source. Empty files remain valid byte inputs. Filenames are not retained. Closing a command dialog, changing ownership or hiding the page cancels pending file reads and fences late callbacks. Identifiers retain their accepted original strings, including leading U+FEFF; malformed UTF-16, null characters, surrounding Unicode whitespace and byte limits are rejected explicitly.

Workflow query is an explicit, audited read against the displayed run/build. It uses an imperative request and local state, with no result cache or polling. Clear query, page hide, target/build change, client replacement, host context clear, accepted local commands or unmount remove private results and fence late replies. Closing the input disclosure discards its draft bytes. Query errors use fixed messages so private handler content cannot appear in diagnostics. Empty output, malformed base64 and non-UTF-8 binary output are distinct; valid text preserves original bytes and numeric lexemes. Revision and sequence counters remain strings. SDK mutation attempts in query handlers are refused by the runtime. That runtime cannot sandbox arbitrary Go side effects, so query handlers still require trusted registration. No human async activity callback form is exposed.

## Real Go browser qualification

Build and start the reviewed host using Dispatch `qualification/README.md`. Its private mode-0600 state file contains real Authsome sessions. Keep it outside the repository. From this dashboard root:

```sh
DISPATCH_OPERATOR_STATE=/absolute/private/state.json \
  pnpm --filter @forge-go/dashboard-shell exec vite \
  --config vite.dispatch.config.ts --port 5291 --strictPort
```

The qualification config binds numeric loopback. `DISPATCH_OPERATOR_ROLE` selects reader (default), payload, commander, denied or anonymous on the server. Use separately configured ports for these checks. Incoming cookies, authorization and authority/forwarding headers are stripped; the proxy applies its configured real session. Every domain POST and the exact GET CSRF route reach the Go host. It has no success fallback. Unsupported dashboard methods/routes are refused. For a bounded lost-response check only, set `DISPATCH_OPERATOR_DROP_FIRST_RESPONSE` to one of `durable.start`, `durable.signal`, `durable.signalStart` or `durable.cancel`. The proxy discards the first genuine accepted 200 response for that intent; retry still reaches the real handler. The fault is disabled by default and resets when the proxy restarts.

The qualification proxy exposes the contract POST and exact CSRF GET routes. It supplies fixture-only shell principal/capabilities documents and restricts the shell to Dispatch. Those documents establish no namespace grants and do not qualify real dashboard login, principal or capability bootstrap. The domain HTTP uses actual Forge transport, stock Authsome-issued sessions, real Warden policies and injected memory or PostgreSQL Dispatch storage. Authsome/Warden fixture stores remain memory; production identity deployment, TLS, production runtime operation, recovery and remote sinks need their own qualification.

The Go fixture seeds unfinished discovery, production/foreign scope, invoice continuation and deliberate source conflicts. Exact large counters and restricted-link fixtures are verified in component tests from the Go wire examples. Boundary-value PostgreSQL row injection was attempted separately and rejected by the required durable delivery intent guard, with its transaction rolled back. No guard was weakened. That artificial high-integer browser boundary remains unverified and establishes no runtime history or recovery claim.
